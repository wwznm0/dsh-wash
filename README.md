# dsh-wash

会话净化：给 DeepSeek Harness 用的侧边栏面板，扫描本地会话记录，把被模型抄进回复里的输入信封剥掉。

## 它解决什么

某些通道（比如 QQ）会在用户消息外面包一层 `<user_message qq="…" nickname="…">…</user_message>`，还会带 `<turn_meta>`。模型有时会把这个信封当成自己的话写回去，甚至替对方续写下一句——一旦被记录，下一轮又喂回来，越滚越脏。

dsh-wash 只做一件事：读出会话记录，把助手消息里从那类标签开始的整段掐掉，备份，重写，自检，失败自动回滚。

## 用法

安装后在左侧栏出现「会话净化」图标：

1. 点「扫描全部」，面板会标出每个会话里有多少条脏消息、浪费了多少字
2. 对单个会话点「洗」，或对选中的会话批量洗
3. 洗之前自动备份到 `~/.dsh/dsh-wash/backups/`；点「还原」用最近一次备份覆盖回去

会话正在被 DSH 写入时按钮禁用，等它空闲再洗。

## 边界

- 只处理 `<user_message>`、`<turn_meta>`、`<assistant_user>` 三种信封标记
- 只改助手消息的文本块，不动用户消息、工具调用、用量记录
- seq 与事件条数原样保留；重编码时首帧只装 header 一行，符合 DSH 的读取约定
- 不联网、不上传；备份只在本机

## 更新

- **0.1.2**：修掉一个会让会话消失的问题。0.1.1 重写记录时把 header 和事件一起每 200 行压一帧，第一帧因此不再只含 header；DSH 下次启动读到这种记录会判定为损坏，直接把该会话从列表里剔除（文件还在，但打不开）。现在首帧单独放 header，自检里也加了首帧行数校验，不为 1 就自动回滚。已经被 0.1.1 写坏的记录，先用「还原」回到备份，再用 0.1.2 重洗。

## 配置

```yaml
- id: dsh-wash
  name: dsh-wash
  config:
    sessionsRoot: 'C:/Users/you/.dsh/sessions'   # 可选
    backupDir: 'C:/Users/you/.dsh/dsh-wash/backups'  # 可选
```
